# Saturday, September 26, 2026

[Wednesday, September 22](2026-09-22-wed.md)

A lot of growing pains because of moving from the Vercel client-only deployment to the Somero.dev domain. Much of it was the problem of waiting for the DNS to settle. But once I had exhausted a few different signals, the waiting was easy enough.

Once the name was resolving, I got working toward making the connection work. For a while, the browser was sounding like it wouldn't accept the certificate. I eventually figured out with a lot of help from Perplexity, google ai mode, and Copilot (using GPT 6 Luna), that:

- the simplest structure for keeping the cert nicely was to have a certbot hook to copy it to the user's home dir and restart the pm2 service (I probably didn't need all the weird `groupadd` stuff)
- I had the `CERT_PATH` and `PRIV_KEY_PATH` swapped for the server env, which we only found once Copilot suggested running the pm2 thing with some certain flag or something to make it log it
- the commands to copy the cert were weird, `sudo install` - why not `cp`?
- the pm2 logs were consistently showing the server saying it would listen but not really listening according to `sudo ss -lunp`. Copilot kept saying it wasn't a failure to loop correctly like I was thinking. It rewrote part of the server script to await the server starting properly before continuing. But that only made the server more honest about listening - it would never even say it was listening anymore. This was what tipped Copilot off that we needed to check deeper logs about server starting.

Also, I started changing the domain by changing the record in Digital Ocean, but it turned out later I needed to change the record from Vercel, I think. It's possible that the Digital-Ocean record was the real one, but when the DNS started working the next day, I had found both records and changed it in both places.
