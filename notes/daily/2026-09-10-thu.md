# Thursday, September 10, 2026

After a long time back and forth with Claude, I got it working. On [this chat here](https://claude.ai/chat/e3055288-6325-4d47-811c-607ac13f85a9).

First, I needed to set up nginx to serve the built vue-client files. We added a nginx file in the sites-available folder. But after restarting nginx, it still wasn't reachable in chrome. It turned out to be because I needed to run the certbot command to auto-edit the nginx server file to include the SSL certificate configuration.

As part of that, certbot asked me if I wanted to change RSA to ECDSA, and Claude said it didn't matter so I kept it as-was.

After that, the vue-client was successfully being served. But it had an error about the handshake failing. From this point, it was fairly straightforward, editing the node server and `git pull`ing and restarting it, until finding out what was going on. The loop was quitting early, and I was passing no 'secret' to the server.

Before that though, we got turned around by some old logs about GLIBC.

Claude had me do `ss -ulnp | grep 4433` to check if the server was listening at all, that's how we discovered the loop was quitting early.

We had to `await` `server.getStream("/count")` to get the session stream properly. And the loop was swallowing the initial error which may have been like either `Error: No secret provided` or `Error: call to method getReader on Promise`.

I set up a certbot timer to renew certificates now, hopefully that helps the budget app as well, but I'll be interested to see. PM2 should be managing the node server restarts automatically. To deploy, I'm doing:

```
git pull
pm2 restart all
```

for the node server, and

```
git pull
npm run build
```

for the vue-client, from their respective folders.
